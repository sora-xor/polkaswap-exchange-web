# Vue 3 Upgrade Roadmap

## Status Snapshot

- Runtime now boots directly on Vue 3; `configureCompat` and the `@vue/compat` alias were removed from `src/main.ts` and bundler configs.
- App shell, navigation, alerts, browser notifications, Moonpay dialogs, and the entire bridge flow (including selectors + transaction details) now run on `<script setup>` with explicit `emits`/`v-model`.
- Legacy mixins were removed (`src/components/mixins`), with their logic extracted into typed composables such as `src/composables/useBridgeCore.ts`, `src/composables/useBridgeTransaction.ts`, and shared utilities under `src/components/**/utils.ts`.
- New Pinia stores (`src/stores/notification`, `src/stores/router`, `src/stores/wallet`) coexist with Vuex modules to phase out decorator-driven access while Composition API components adopt store helpers.
- Bridge, settings, wallet connection, staking, vault, and IPFS tooling now have Vitest coverage mirroring the new composables (see `tests/unit/components/pages/Bridge/SelectNetwork.spec.ts`, `tests/unit/modules/vault/metrics.spec.ts`, `tests/unit/utils/staticAssets.spec.ts`).
- Translation plan remains tracked in `docs/plans/vue3-migration.md`; detailed audit workflow lives in `docs/plans/translation-audit.md`. Continue running `yarn test:translation` after each flow conversion to keep locale catalogs in sync.
- IPFS release tooling now lives in TypeScript (`scripts/ipfs/publish.ts` + `scripts/ipfs/check-*.js`), and static asset helpers enforce gateway-safe paths across environments.
- Opt-in compat-free builds can be generated by setting `VITE_DISABLE_COMPAT=true` (exposed via `yarn build:vue3`) to validate native Vue 3 output.
- Pinia stores now wrap assets (`src/stores/assets`), settings (`src/stores/settings`), swap (`src/stores/swap.ts`), wallet (`src/stores/wallet`), notification, and router modules; Options API holdouts still read through `direct-vuex` adapters until their Pinia counterparts replace them.
- Class-based single-file components are down to roughly 45 (`rg '@Component' src/components`), concentrated in Sora Card, Order Book, Pools, and Rewards dashboards; the remaining conversions are tracked per workstream below.
- Vitest suites exercise the new Pinia stores (`tests/unit/stores/*.spec.ts`) alongside bridge and Moonpay composables, giving guardrails while we replace the legacy mixins and Vuex decorators.
- Assets and web3 composable expansion plan defined (`docs/plans/assets-web3-composables.md`) to consolidate formatting logic and prepare wallet dialogs for Pinia-only state.
- Roadmap execution runs on an eight-week migration cadence with two-week review checkpoints to track compat removal readiness and wallet-library delivery.
- KPI baselines (class components remaining, Pinia parity score, compat build pass rate, bundle diff) are monitored weekly—see “Progress Tracking & KPIs” for targets and reporting cadence.

## Architecture Remediation Plan

This track hardens the application architecture beyond the Vue 3 migration so IPFS builds stay stable and new features land on predictable layers.

### Goals

- Eliminate the global direct-vuex dependency by moving durable state into Pinia stores and exposing the minimum interop surface necessary for legacy components.
- Break the router monolith into feature-owned route modules with testable guards while keeping wallet-specific navigation logic isolated.
- Treat the vendored wallet and utility stacks as true external dependencies by wrapping them in typed adapters so app code never imports `@wallet` internals directly.
- Untangle shared utilities from singleton side effects, allowing vitest suites to exercise them without spinning up the full app.

## Metrics & Exit Criteria

- **Compat retirement**
  - Zero imports from `@vue/compat` or `src/compat/*` after build analysis.
  - `yarn build:vue3` equals `yarn build` artefacts (bundle diff <1% by size) with Vue warnings cleared.
  - Nightly compat smoke build green for seven consecutive runs.
- **Component conversion**
  - No remaining `@Component`/class decorators in `src/components/**` (tracked via lint or Codemod report).
  - All migrated components include Vitest suites covering emits/reactivity with translated copy verified through `yarn test:translation`.
  - Accessibility checklist applied to each converted dialog/widget (focus traps, keyboard nav).
- **State layer migration**
  - Pinia stores provide all getters/actions previously exposed by Vuex modules; parity verified by unit tests (mirror suites in `tests/unit/stores/**`).
  - `src/store/**` gradually reduced to composable adapters; once unused, modules removed without regressions.
  - Bridge and swap flows consume Pinia stores in production telemetry (tracked by feature flag instrumentation).
- **Library uplift & cleanup**
  - Soraneo wallet and UI libraries publish Vue 3 builds with typings; project consumes them without shims.
- Legacy stylesheets audited; unused `.compat` overrides deleted post-visual QA.
- Documentation (`README`, `docs/plans/vue3-migration.md`, onboarding) reflects new architecture and workflows.
