# Study snapshot validation

The durable study store uses `assertGoalQualificationOwnData` before serializing a snapshot. This calls the exact existing qualification copy validator, including all own-descriptor, prototype, dense-array, safe-number, depth, node and string limits. It still allocates and freezes the checked detached copy; the store then preserves its original canonical serialization, size check, JSON normalization and fresh frozen output.

The assertion returns no proof or capability and creates no cache. Every call checks the incoming value again. It removes only the SHA and canonical serialization whose result the snapshot previously discarded. Qualification digests, persisted evidence digests, raw wrapper byte rereads, completion verification and independent ledger reconstruction remain mandatory and unchanged.

The continuation export test retains its original failed-parent evidence, six complete synthetic qualification episodes, independent persisted episode reverify, all byte-for-byte publication assertions and its 60-second deadline. A scoped timeout or pass does not establish a full gate result or the dominant cost of that callback.

Qualification digests use `sha256AsU8a(bytes, true)`, selecting the existing JavaScript SHA-256 engine through its second argument. The exact own-data validator, canonical byte order, UTF-8 encoding and hexadecimal digest remain unchanged. This matches the existing ledger engine choice; it changes no initialization, signature API, protocol, used checksum or source authority.

The Node equivalence suite initializes the default WASM engine, then compares real default and JavaScript SHA with independent Node crypto over known canonical data, including Unicode keys and lone surrogates. It also keeps depth, invalid-shape, mutation, getter and revoked-proxy rejection checks. The earlier candidate timeout receipts remain retained; neither an engine microbenchmark nor a CPU profile proves a deadline or full-gate pass.

Regular durable record reads parse the bounded file into a private JSON graph, then use `copyGoalQualificationOwnData` to run the same complete validator and obtain its detached, recursively frozen result. They serialize that result once, enforce the canonical UTF-8 byte limit, and require the original decoded file text to equal that exact serialization plus one newline before returning it. This removes only the second JSON parse, second freeze traversal and duplicate serialization of regular records. Canonical text equality still rejects alternate numeric spellings (including negative zero), duplicates, escaping, key order and whitespace; validation and byte-limit errors retain their earlier precedence.

This seam applies only to the private fresh parse inside regular `readRecord`. Ordinary untrusted snapshots retain their original caller traversal, JSON normalization and freeze behavior. Raw metadata uses its unchanged `rawSnapshot` bounds and is reread on every replay. Filesystem flags, stat and chunk caps, fatal UTF-8 decoding, newline checks, all compared digests, source/receipt bindings, and independent qualification and ledger reconstruction remain unchanged. The copy helper returns data rather than an authority handle and never caches or aliases caller objects.

The new regular-record suite uses real local journal operations, without exposing a private reader or mocking validation. It checks fresh frozen replay output, canonical spellings and UTF-8 limits, validation precedence, non-followed symlinks, unchanged metadata above the qualification string cap, and rejection after a persisted raw wrapper changes. The V2 equivalence files and all original fixtures, assertions and deadlines remain untouched. The retained V1/V2 60-second failures remain failures; this proposal has no measured speedup or passing-gate claim.

Completed-record replay uses a module-private evidence binding check at the same final position after all completion hashes and raw receipt/file rereads. The full regular parent record already checks and freezes every evidence descendant. Its aggregate node/string/depth bounds imply the subtree bounds, and canonical evidence bytes are a verbatim subtree of the already capped parent serialization. A second evidence snapshot would pass those same bounds and return equal data; its discarded copy is unnecessary. All actual evidence/request hashes and evidence field, version, protocol, data-digest and time-window checks remain mandatory.

Ordinary `evidenceFor` still snapshots caller data first and returns that snapshot. The binding helper has no export, flag, cache, brand or authority handle. Raw metadata and independent qualification/ledger reconstruction remain unchanged. The new journal tests independently rehash semantic impostors, preserve hash/raw/semantic rejection order, exercise parent depth and noncanonical admission, and retain transparent proxy traversal plus caller signed-zero/null-prototype normalization and accessor/revocation rejection.

The bounded read-only findings in `output/go-history/bots-completion-audit-20260930/post-v3-completed-evidence-readonly-20261001/findings.json` explain this seam. Original CPU samples establish the earlier call chain, not its current cost or share of the timeout. The retained V3 original 60-second failure remains failed. The original V4 proposal remains retained in output. Its guarded canonical integration is under validation; no performance improvement or full gate result is established until the unchanged relevant tests and full gate pass.

Journal publication writes and syncs an exclusive temporary file, creates the final name with a hard link that cannot replace an existing record, removes the temporary name, then syncs the directory once before reporting success. This makes both namespace changes durable together. A crash before that last sync can leave incomplete publication, and no successful result is returned before it. Cleanup failures still trigger an attempted directory sync and retain their previous error precedence. The fault-injection suite checks this durable-return barrier, exclusive publication, failed file/link/cleanup/directory operations, and fresh replay rejection after raw evidence changes. This optimization changes no persisted bytes, checksums, ownership or qualification rules.

Raw snapshots retain their exact checked canonical text beside their detached, frozen data within one private operation. Receipt hashes and byte counts use that text, and raw publication uses the text from its separate full-envelope validation. Every outer wrapper still undergoes its own node, depth, string and byte checks before file creation; names and aggregate quotas are reserved before the first await. No caller-supplied serialization, cross-call cache or replay shortcut is accepted. Exact Unicode/escaping and signed-zero bytes, fresh corruption, rejected accessors/cycles and wrapper-depth failure precedence are covered by real journal tests. All per-record file and directory syncs remain required; removing repeated serialization alone is not evidence of a passing archive deadline.
