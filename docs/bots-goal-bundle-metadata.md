# Browser callback metadata verification

`verifyGoalBundleMetadata(binding, { readArtifact, signal? })` reconstructs the original training callback collection offline. It returns a frozen, privately owned `GoalBundleMetadataVerification` with `blocks`, inclusive `firstHeight`/`lastHeight`, and provenance. `assertGoalBundleMetadata(result, binding)` rejects a copied JSON projection or a result created under different pins. There is no network, filesystem, wallet, trade, strategy selection or qualification operation in this module.

The caller supplies pins from its externally trusted archive/bundle index. `manifestSha256`, `verificationSha256`, `rawManifestSha256` and `blocksFileSha256` bind exact original file bytes. `blocksSha256` separately binds the original archive input's `JSON.stringify(blocks)` with no added newline; original block property order is preserved after every value is independently reconstructed. The callback builder normalizes its own block objects and computes its own digest. Neither identity is substituted for another.

`readArtifact(name, signal)` supplies original UTF-8 bytes under the exported logical namespace: `run-protocol`, `verification`, `raw-manifest`, `blocks-training`, `group-NNNNN.complete`, `group-NNNNN.batch-NNNNN` and `shard-NNNNN.complete`. The pinned raw manifest authenticates byte lengths and file hashes. The pinned verification must name the same protocol, source hashes and complete training partition. Protocol ranges, schema identity and original derived collector budget are rechecked before block reconstruction. The ordinary verifier admits training only. `verifyGoalBundleValidationMetadata(binding, dependencies, { selection, binding: admissionBinding })` is a separate guarded entrypoint: it requires the live owned selection from the completed-study adapter before any file read and throughout verification. It never reads market data.

For each training-connected transport group, it reads every original batch and every member shard. A neighboring member can belong to a different collector range, but contains metadata only. Complete HTTP 200 bodies must match original lengths and hashes. Exact JSON-RPC requests, deduplication mappings, wire IDs and logical IDs reconstruct the original projected response for each shard receipt. A multiset conservation check requires every original wire-to-logical join exactly once, with no missing or extra receipt. Group/shard hashes, counters, pacing and aggregate bounds are checked independently of the pinned verification report.

Each shard reruns the original block-reader sequence: mainnet genesis, observed finalized head, canonical source/anchor hashes and headers, runtime identity, code hash, metadata layout, then each canonical block hash, header, matching code hash and exact SCALE Timestamp.Now value. The shared browser codecs verify full header structure, storage layout and u64 timestamp decoding. Reconstructed block values must equal both the original shard projection and the separately pinned contiguous training array. No saved normalized block projection is accepted alone.

The provenance includes the original finalized-source and schema-anchor identities, runtime/storage schema, source hashes, raw group/batch/shard references, wire acquisition times and logical acquisition endpoints. These remain audit timestamps. `arrivalTimeKnown:false` is explicit: modeled callback arrivals come from the separately bound callback builder, never from when the browser downloads these files. `attestation:'rpc-canonical-finalized'` describes the original RPC trust boundary; this is not GRANDPA signature verification, a trie proof, or independent cryptographic consensus verification.

Reads are single-use and bounded (25,004 artifacts, 8 MiB per ordinary file, 32 MiB block array, 4 GiB cumulative bytes). Each dependency read receives an abort signal with a 30-second limit; caller abort rejects pending reads. Parsed JSON is bounded by depth, nodes, collection size and safe integers. All source/evidence values are detached before use, and the owned result is deeply frozen.

`tests/fixtures/bots/goal-bundle-metadata.ts` uses the actual collector and block reader against invented real-codec responses. Its configurable interval, range and metadata allow full episode-source tests to obtain genuine owned verification results without mocking authority. Focused tests exercise exact original-byte pins, wire/logical conservation, rehashed semantic corruption, volatile acquisition epochs, aborts and distinct file/archive digests. They read no actual study or validation data.

Validation ownership is bound to the same index, plan, evaluator source and selected candidate. `assertGoalBundleValidationMetadata` additionally requires the identical private selection capability. The two exact selected validation request hashes may share one verified partition cache; another request or candidate cannot use it. Disposing the study revokes the capability and previously returned validation metadata. JSON copies cannot reopen it. Training admission remains unchanged.

## Catalog collection v2

`verifyGoalBundleCatalogMetadata(binding, { catalog, readArtifact, signal? })` is the explicit training entrypoint for `qualification-callback-metadata-catalog-v2`. Its validation counterpart is `verifyGoalBundleCatalogValidationMetadata(binding, dependencies, admission)`. Both require an actual privately owned `GoalRuntimeCatalog`; the existing v1 constructors still reject v2 protocols. The existing general assertions accept either owned result, while `assertGoalBundleCatalogMetadata` and `assertGoalBundleCatalogValidationMetadata` additionally require the catalog result and can bind the exact catalog instance.

The result has `kind: 'goal-bundle-catalog-metadata-v2'`, catalog-specific provenance, and `blockProfiles`. `profileForBlock(hash, height)` returns the verified association for that exact block, including the full catalog profile with genesis identity. The clock `blocks` remain the original four-field objects. Associations are separate evidence and do not change callback clock digests. Catalog result operations reject after caller abort; validation results also reject after their selection is revoked.

Verification replays the collector's twenty initialization requests, including all three canonical schema anchors, and four requests per block. Every anchor's metadata bytes, runtime identity and code hash must match its owned catalog entry. Every per-block code hash must match an authenticated source profile and the retained `blockProfiles` sidecar. A repeated block cannot claim conflicting profiles, including across anchor and shard reads. Original wire responses and mappings remain authoritative: rehashing a shard, profile association, or projected RPC cannot replace the original wire result.

The v2 limits are explicit: at most 64 blocks per shard, 2 MiB per logical response, 6 MiB summed logical response bytes per shard, 552 wire batches per transport group, and 12 GiB cumulative artifact reads. Protocol-derived finite request and byte budgets are checked exactly. These bounds do not expand the v1 limits. File-byte pins and normalized clock/value digests retain their distinct meanings.

`tests/fixtures/bots/goal-bundle-catalog-metadata.ts` runs the actual Node collector against invented responses and genuine pinned runtime metadata. The browser tests reconstruct all three profiles, an invented rollback, original-wire joins, contradictory repeated-block claims, cancellation and an actual owned validation selection. They make no network requests and read no economic study data.

`getGoalBundleVerifiedMetadataCatalog(result)` retrieves the exact private catalog for a live catalog result. It rejects legacy results, JSON copies, caller abort and revoked validation selection; it does not infer authority from serialized profile fields.
