# Swap quote and review behavior

The swap form keeps minimum received (or maximum sold for exact-output trades) and named price impact visible above its primary action. Unavailable quotes show a dash. Above a 1024px viewport, Fees and trade details are always shown below the action with no collapse control, including while a quote is unavailable. The desktop heading keeps the original small, centered uppercase label, and the content retains the disclosure's neumorphic surface without an outlined border. At 1024px or less, the same content uses the inline disclosure. Resizing updates this presentation without changing the trade or saving a layout preference.

`services/readiness.ts` separates verified route absence from failed RPC evidence. Route and initial quote requests time out after 15 seconds. Retry refreshes read-only quote data and preserves the pair, entered side, amount, and slippage. A lifecycle generation invalidates callbacks and timers after retry, pair changes, disconnect, and unmount.

`services/feeAssessment.ts` computes XOR fee shortages using codec strings and chain precision. Native input can use the existing Max action, which reserves the native fee margin. Native output may cover the fee only when positive output remains. Exact shortages are hidden when balances are hidden. Receive XOR opens in place so the swap draft remains mounted.

`types/review.ts` describes captured trade terms and signing identity. Confirm is controlled by the form: invalidation keeps it open, changed terms require explicit review, and wallet rejection preserves the draft. Submission takes a lock and revalidates the captured terms after wallet preparation, immediately before executing. Only a successful `withNotifications` submission result closes review and clears amounts. Neither quote retry nor review refresh submits a transaction.

Behavioral regression tests live in `tests/unit/components/pages/Swap` and pure evidence/amount tests in `tests/unit/features/swap`. These use mocked wallet and RPC dependencies; they do not sign or access external services.

The Swap header contains the page customization menu. Default desktop layouts use equal form and chart columns. Above a 1024px viewport, the grid selects at least the saved small-desktop layout even when the sidebar reduces its container width; it does not rewrite saved geometry. At viewport widths of 1024px or less, a presentation-only vertical stack places the form first, followed by the chart disclosure and optional widgets. The chart starts closed and mounts a 360px body when opened; hiding the chart through customization remains a separate saved preference. Dragging and resizing are available on larger screens, while widget visibility and Reset remain available on mobile.

Saved layouts keep the `swapGrid:v3` storage key and its existing IPFS CID scope. A one-time migration detects and removes the legacy Customize widget, updates untouched desktop geometry, preserves custom desktop geometry and hidden widgets, and stacks existing narrow-layout widgets. Only explicit widget changes or drag/resize gestures persist; opening the chart or resizing the viewport does not save presentation geometry. Reset restores default visibility and layout and closes the disclosure. Leaving Swap clears transient state after grid watchers are disposed, so returning can hydrate the saved layout safely.
