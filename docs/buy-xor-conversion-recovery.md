# Explicit conversion replacement recovery

Ethereum wallets can speed up a pending conversion by submitting the same request at the same nonce with different gas terms. Polling only the original hash would never discover the replacement. The purchase journey now captures a request fingerprint and accepts an explicitly supplied replacement hash only after checking the exact request and its canonical receipt.

`captureGetTsConversionFingerprint(client, originalHash, account, purpose?, isCurrent?, storage?)` reads that exact hash from the already selected Ethereum mainnet provider. It validates the currently connected account and gateway transaction before saving one versioned entry per purpose. The entry contains only the original public transaction hash and a SHA-256 digest of chain ID, sender, nonce, gateway, calldata and value. Raw addresses, calldata, amounts and status are not stored. Gas price/limit are excluded so a repriced transaction can match. The existing `useGetTsConversionProgress` reader starts this capture beside ordinary receipt polling; it survives the signing panel's unmount and does not delay progress. Capture retries on later polls if the provider has not yet exposed the transaction. Storage denial leaves ordinary progress usable but prevents later digest-only recovery.

`verifyGetTsConversionReplacement(client, originalHash, replacementHash, account, purpose?, isCurrent?, storage?)` prefers the original transaction when it remains available. When the original is evicted, a matching bounded purpose/hash fingerprint is required. The replacement must have exactly the same sender, nonce, chain, gateway, calldata and value. A cancellation, unrelated transfer or different conversion is rejected. The helper then reuses `readGetTsConversionProgress` to verify a canonical Ethereum receipt and exact net canonical DAI transfer logs. Only `received` or `failed` may authorize the UI to replace the tracked hash; pending/unavailable evidence never completes or restarts a transaction.

Calls are bounded to 15 seconds and reject late results after account, provider, purpose or reference changes. The reader does not connect a wallet, request signatures, resend transactions, scan arbitrary history, or infer payment from a balance. The existing one-confirmation Ethereum policy is unchanged. If an old transaction was evicted before any fingerprint was captured, automatic replacement attribution is intentionally unavailable; a wallet balance remains a separate explicit existing-funds route.

Tests cover exact digest identity and bounds, per-purpose storage, evicted originals, cancellation/different request rejection, canonical receipt output and failure, context/network changes, denied/malformed storage, stalled RPCs and nonblocking capture from the shared progress composable. No test performs a financial transaction or network request.
