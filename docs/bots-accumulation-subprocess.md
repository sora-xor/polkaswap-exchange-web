# Accumulation subprocess transport

`runAccumulationSubprocess` in `scripts/bots/accumulation-subprocess.ts` invokes one fixed Python worker once. The only choices are `admission` (`scripts/bots/accumulation_admission_runner.py`) and `journal` (`scripts/bots/accumulation_journal_replay.py`). It never parses a result, chooses a trade, owns a journal, accesses a wallet or retries.

The trusted caller supplies a canonical repository root, the resolved absolute Python executable, exact input bytes, bounded limits, and interpreter/source SHA-256 pins from its independently authenticated registration. A hash discovered from the current file is not trusted registration. Admission requires exactly its runner, admission policy and stopping-model source. Journal requires exactly its worker, execution replay, admission runner, admission policy and stopping-model source. Missing, duplicate or extra source paths fail before spawn. Source and executable paths must resolve to themselves and be regular files; symlinked components fail verification. The interpreter binary and sources are checked before and after invocation. This is a consistency check, not an operating-system sandbox, an atomic executable snapshot, or a pin of the interpreter's entire standard library. The workers retain their own source/model verification duties.

The command uses the pinned executable directly with `-I -S -B`, the fixed absolute worker path, no shell and only `LANG=C`, `LC_ALL=C`, `TZ=UTC` in its environment. There are no caller-selected arguments or environment fields. The admission input cap is 256 KiB; the journal transport input cap is 2 MiB. Journal semantics separately enforce the 1 MiB / 512-record history bound. Output caps are 256 KiB stdout and 64 KiB stderr; runtime is at most 60 seconds. Callers may choose smaller positive limits.

The receipt retains exact input SHA-256, observed and retained stream digests, bounded base64 output prefixes, byte counts, truncation, exit/signal/error facts, all termination requests and actual wall/monotonic clock samples. An oversized input is not copied or hashed. Each stream's observed digest covers all bytes actually delivered before transport finalization; it is not a digest of unseen bytes after truncation or termination. Runtime covers the child lifecycle; overall receipt time also includes pre/post local file checks.

A timeout, stream cap or I/O error sends SIGTERM to this child handle, then SIGKILL after 250 ms, then ends receipt collection after another 250 ms if no close arrives. A signal sent or accepted does not prove termination: `closeObserved:false`, `terminationUnconfirmed:true` and `outcomeUnknown:true` retain that uncertainty. The helper never kills unrelated processes or relaunches a worker. It destroys its pipes and removes process lifetime references if bounded collection must end without close.

`outcome:'completed'` means only zero exit, confirmed close, completed input write, untruncated/error-free transport and unchanged post-check hashes. `resultAuthority:false` is unconditional. Before any policy invocation the parent must own the verified evidence packet and authenticate the untouched episode journal; after computation it must parse and bind the output, compare the expected journal head and re-check quote/context freshness using the recorded actual finish time. This helper provides none of those authorities. Returning bytes to a caller does not persist a journal; the parent must durably record the invocation and resulting receipt.

`createAccumulationSubprocessForTests` is a separate, explicitly named fake-child/clock boundary. Production orchestration must call `runAccumulationSubprocess`, which always uses real Node spawn. Tests use invented files and a minimal Python echo worker at the fixed fixture path; no model file, market data or network service is required.

yarn vitest run --project unit-scripts tests/unit/scripts/bots/accumulation-subprocess.spec.ts
