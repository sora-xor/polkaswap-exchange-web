# IPFS Toolchain Upgrade Plan

Major releases of the IPFS UnixFS stack (`ipfs-unixfs` v12, `ipfs-unixfs-exporter` v15, and `ipfs-unixfs-importer` v16) landed after our last dependency sweep. This document captures the upgrade work needed to bring the Polkaswap toolchain up to date while keeping the static build scripts and Vitest stubs working.

## Current State

- **Pinned versions** – `package.json` and Yarn resolutions lock the trio to 6/7/9 (`package.json#L139-L143`, `yarn.lock`). These older bundles expose CommonJS entry points and expect legacy chunker/layout helpers.
- **Stubbed modules** – Unit tests use lightweight shims under `tests/stubs/ipfs-unixfs-importer/**` with a Vite alias defined in `vite.config.mjs#L52-L63` to avoid pulling heavy DAG tooling into Vitest.
- **Script expectations** – `scripts/ipfs/check-browser.js` and `scripts/ipfs/publish.ts` rely on the CLI layout generated by the pinned packages. The publish script currently shells out to the `ipfs` CLI (`scripts/ipfs/publish.ts#L142-L209`) and assumes the `add -Qr` behaviour that depends on UnixFS importer defaults.
- **Postinstall patching** – `scripts/postinstall/fix-peer-deps.js#L111-L140` reaches into `ipfs-unixfs-importer` to relax peer dependency ranges, mirroring the old workspace layout.

## Upgrade Tasks

1. **Research upstream breaking changes**
   - Review release notes/changelog for UnixFS v12+ to confirm new module entry points (ESM default, renamed chunker/layout helpers, updated DAG builder options).
   - Capture any runtime flags that affect `ipfs add -Qr` defaults (CID v1 vs v0, raw leaves, hashing).

2. **Update dependency graph**
   - Bump the three UnixFS packages to the latest compatible majors in `package.json` and drop the resolution overrides.
   - Re-run `yarn install` to update `yarn.lock`, verifying no additional peer conflicts surface in other DAG/Multiformats packages.

3. **Refresh Vitest stubs and aliases**
   - Mirror the new export surface in `tests/stubs/ipfs-unixfs-importer/**`, including any renamed `chunker`/`layout` modules or default exports.
   - Update the alias logic in `vite.config.mjs` if upstream switches to fully-qualified subpath exports (e.g., `ipfs-unixfs-importer/chunker/raw`).
   - Extend `tests/setup/vitest.setup.ts` mocks so importer/exporter consumers keep working without the real binaries.

4. **Audit project scripts**
   - Exercise `scripts/ipfs/check-browser.js` and `scripts/ipfs/publish.ts` against a temp workspace using the new packages, adjusting error handling and log parsing where CLI output diverges.
   - Ensure `publish.ts` still enforces Vue 3 builds in sibling workspaces; capture any additional build prerequisites introduced upstream.
   - Update `scripts/postinstall/fix-peer-deps.js` (or delete the workaround) depending on whether v16 resolves the peer range issues.

5. **Validation & regression coverage**
   - Add targeted unit coverage around any new helper utilities we introduce while updating the stubs/scripts.
   - Run `yarn test:unit`, `yarn test:translation`, and the IPFS smoke scripts (`yarn ipfs:publish`, `yarn ipfs:check --cid <test-cid>`) to verify end-to-end compatibility.

## Open Questions / Follow-ups

- Should we preserve a fallback branch for users still on the Kubo 0.18 CLI, or can we assume the gateway nodes are already upgraded?
- Can the importer/exporter version bump unblock removal of the bespoke `fix-peer-deps` script entirely?
