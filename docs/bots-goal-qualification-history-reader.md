# Qualification indexed history reader

`readGoalQualificationHistory({startAtMs, endAtMs, genesisHash, denominator}, options)` in `scripts/bots/goal-qualification-history-reader.ts` reads only the fixed mainnet KUSD→XOR pair, with native XOR as fee asset, from `https://pi.soramitsu.io/graphql`. Both assets use explicit 18-decimal metadata, verified by the actual `parseIndexedPoolHistoryWithEvidence` decoder. This additive source does not activate a bot, evaluate a strategy, grant qualification or alter the production history fallback.

The input is an aligned **opening-bucket `[startAtMs, endAtMs)`** range of 1–201 hours. Its completed candles run from `startAtMs + oneHour` through `endAtMs`, inclusive. For a 200-close warmup whose first completed close is June 5 20:00, request buckets starting June 5 19:00. At the first June 14 04:00 signal, retain all 200 earlier warmup closes **plus** the current completed close: query `startAtMs = completedAtMs − 201 hours`, `endAtMs = completedAtMs`. This is 201 candles and six pages at the maximum range; the warmup itself remains 200 hours. The reader requires the caller's exact mainnet genesis and positive u128 denomination; it does not infer or normalize another epoch.

The GraphQL query requests canonical IDs, asset/type/timestamp, denomination and full `closeEvidence` for KUSD and XOR. It never requests USD prices. Both assets paginate in timestamp order using the exact original filter and opaque cursor. Duplicate IDs/hours, wrong assets, noncanonical IDs, out-of-range/unordered rows, cursor cycles, empty continuing pages, GraphQL errors and incomplete histories reject the operation. Missing, malformed, legacy or mismatched pool evidence cannot be replaced with another hour or a USD peg.

Successful output is a deeply frozen `{history: IndexedPoolHistoryWithEvidence, rpcEvidence}`. Indexed block timestamps remain seconds; adjacency/hash provenance does not pretend to supply exact canonical millisecond timestamps or parent proof. Historical RPC verification and modeled availability/receipt-time binding belong to the trusted evaluator. Actual `requestedAtMs`/`completedAtMs` on raw HTTP receipts describe this fetch, never a historical browser arrival.

The complete operation defaults to 20 seconds, with a caller cap of 30 seconds, including cursor pages, response bodies and decoding. It allows at most 8 HTTP requests, 100 edges/page, 2 MiB/response, 8 MiB total, and 201 canonical rows/asset. There are no retries, redirects, endpoint substitutions, wallet calls or transaction operations. Abort/timeout stops awaiting even a noncooperative fetch/body; later data is ignored and a late fetch response body is canceled. Options are validated by descriptors and copied before awaiting; replacing the caller’s fetch, signal or deadline cannot change an in-flight operation. Explicit null options/fields and accessor options are rejected.

`GoalQualificationHistoryReadError.diagnostic` carries a bounded stage/reason and immutable raw receipts, including incomplete prefixes where available. Error messages never interpolate remote text or market values. Raw receipts contain pool observations and must be retained privately rather than printed to the model or console. Actual study calls must pass through the preregistered training/validation access gate; possession of this reader or an opaque digest is not qualification authority.

Tests use invented reserves and a mocked endpoint only. They exercise the actual pool decoder, one-atom precision, pagination, malformed/missing proofs, raw error retention, descriptor checks, input mutation, byte/request limits and operation-wide deadline/late-response handling. No real training, validation or other market dataset is read during implementation or tests.
