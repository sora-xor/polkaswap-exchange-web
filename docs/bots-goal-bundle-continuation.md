# Browser continuation evidence

`createGoalBundleContinuation()` in `src/features/bot-trading/goal-bundle-continuation.ts` is the concrete read-only dependency for `GoalBundleStudyContinuation`. `createGoalBundleAcquisition()` supplies the ordinary acquisition observer for every later training and validation episode in that continuation child. The application passes both directly to the study verifier; bundle JSON cannot supply executable verification functions.

The shared implementation of `prepareGoalAcquisitionReplay` now lives in `src/features/bot-trading/goal-acquisition-replay.ts`. The original script re-exports the same API. Hashing and byte counts use browser-compatible SHA-256 and UTF-8 helpers. Existing live replay and ownership checks remain unchanged. Sealed source copies and retained study records are not modified.

Preparation reads every file in the original pinned parent inventory, checks exact file hashes and lengths, raw envelopes, registration/access/failure bindings, metadata-cache joins and both ordered request lanes. The browser study reader additionally binds that entire inventory to its immutable bundle index and validates continuation lineage. Preparation remains privately owned; serialized copies cannot replace it.

The original script preparation has its existing 30-second whole-operation limit. `prepareGoalAcquisitionReplayBundle` explicitly uses a 30-second limit for each pinned artifact, plus the original caller's abort signal and the same total file/count/byte limits. This permits distribution of many immutable objects over HTTP. It does not alter the recorded acquisition deadline, historical callback model, fee policy, candidates or training/validation boundary.

The child observer accepts each exact wrapper value once. Semantic responses arrive in the original evaluator's causal order; provenance receipts may arrive later in sorted filename order. The verifier therefore:

- Checks every saved prefix-use record against private parent lanes, including lane sequence, original envelope digest, request/response hashes, cache name and the retained 502 boundary.
- Requires both parent lanes to be drained at the causal failed-request boundary and matches both parent response prefixes against the child's ordered semantic response lanes. The next child history response must consume the exact previously failed request's successful retry.
- Checks every retained acquisition attempt's exact history request, policy digest, complete response bytes/Base64/hash, operation identity, deadline, retry sequence and recorded backoff between attempts. The first resumed request carries exactly one original failure; subsequent requests start at attempt one. There are at most three attempts total per request.
- Joins each successful physical history response to one child history response, rejects orphan attempts and counts the original failure and all additional error attempts/bytes exactly once against the unchanged aggregate limits. Each history artifact identifies one reader operation: its replayed and fresh successful pages, original boundary failure and additional error attempts together remain within the original 8 MiB operation cap.

This concrete adapter binds the approved runner's fixed 20-second operation timeout as a source-composition requirement; the generic original transport still allows up to 30 seconds. The timeout is not independently encoded as a duration in attempt records. The original per-operation creation timestamp is not present in an attempt receipt. The verifier checks its immutable recorded deadline, a maximum 20-second remaining interval, monotone nonoverlapping attempt times and every subsequent recorded retry delay; it does not invent an unrecorded first-attempt start timestamp. Acquisition responses remain evidence, not historical arrival-time claims. The actual economic source/evaluator independently validates history, quote, fee, clock and terminal evidence.

This module performs no fetch, market acquisition, retry, wallet access, signing or transaction submission. It creates neither a live replay completion token nor a qualification. Any malformed record or abort permanently closes that observer. The completed-study verifier remains responsible for recomputing training, sealing selection before validation and comparing the final certificate.

Both factories share the same attempt/response/operation-budget reducer. Only the first factory can receive the privately verified parent preparation. The ordinary factory binds the complete expected episode request, requires retained attempts for every history response, starts each request at attempt one with zero carried failures, rejects prefix reuse, and adds no original-failure surcharge. This closes a composition gap where later acquisition files were hash-checked without recomputing their retry or per-operation limits. The study adapter requires this observer for every later continuation-child episode, after the normal validation admission gate. Legacy non-continuation studies retain their existing behavior. Source filenames do not provide a bypass from the child-lineage requirement.

Validation is retained in `output/go-history/goal-bundle-continuation-verifier-20260921/`. The synthetic suite includes a successful resumed request, a further temporary outage, browser execution with `Buffer` removed, altered prefixes and responses, missing/duplicate uses, wrong order, changed retry requests, reset carried attempts, insufficient backoff, incomplete bodies, orphan attempts, omitted original failure costs, abort, getters and distribution timeout behavior. Later training and validation cases also cover exact budgets without an invented surcharge, fresh retries, missing physical attempts, unexpected carry, reused prefixes, changed episode requests and omitted retry costs. No actual study or validation data was read for this work.
