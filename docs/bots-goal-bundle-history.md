# Browser raw history verification

`goal-bundle-history.ts` adds `verifyGoalHistoryArtifact(bytes, binding, context, metadata)` for a future browser `GoalEpisodeEvidenceSource`. It performs no network, filesystem, wallet, strategy selection or qualification operation. It verifies successful v2 `history-<checkId>.json` artifacts only; pending history and validation admission remain outside this module.

The caller supplies exact original wrapper bytes from the pinned bundle reader, an expected `GoalRawEnvelopeBinding`, causal context from its verified source/clock, and the exact inclusive `firstHeight`/`lastHeight` coverage plus a function that looks up already raw-verified canonical blocks by height. Context and a JSON record claiming that metadata was verified are not interchangeable. The verifier's plain evidence result is intended for an already trusted evidence source; it is not an authorization capability or proof that the data was unopened.

The original store has two different SHA-256 identities:

- The **file-byte hash** covers the exact UTF-8 wrapper, including its final newline. The bundle reader verifies this against the external pinned manifest.
- The **value digest** covers sorted-key canonical JSON of the wrapper's `value`, without a newline. The wrapper's `sha256`, the expected `valueSha256`, and returned `evidenceSha256` must all equal this original digest.

`goal-raw-envelope.ts` joins these layers. `readGoalRawEnvelope` accepts only the original five-field `goal-study-raw-evidence-v1` wrapper, in canonical encoding plus one newline, with its expected request digest and logical name. It recomputes the canonical value digest and returns a deeply frozen value. Its shared `goalRawEvidenceDigest` and `goalRawBytesSha256` use browser-compatible SHA-256. Inputs have 32 MiB encoded bounds, depth 24, 800,000 nodes, arrays up to 30,000 entries and objects up to 64 fields. Accessors, extra array properties, unsafe numbers, undefined values and non-data prototypes fail before use. Large retained metadata strings are supported without routing through the smaller qualification JSON contract.

History is independently rebuilt from the original raw GraphQL receipt bodies. Each request must exactly match the fixed query, KUSD then XOR order, expected opening-time range and original cursor chain. All receipts must be complete HTTP 200, with consecutive indexes/pages, matching UTF-8 body lengths and SHA-256 hashes. The original maximum of eight pages, 2 MiB per response and 8 MiB total is enforced. The fixed window contains **201 completed hourly observations: 200 warmup hours plus the latest hour**. Duplicate identities, missing hours, incorrect assets or intervals, cursor cycles and GraphQL errors fail.

`parseIndexedPoolHistoryWithEvidence` recomputes the full paired history from exact XOR pool reserves. Both assets must have the same accepted boundaries, mainnet genesis and denominator. Every candle and boundary must exist, and this reconstructed history must equal the saved normalized projection. That comparison detects inconsistency; the saved projection itself is never returned as authority. Within the trusted metadata's inclusive coverage, every indexed closing block and immediate successor must be present and match height, hash, second-resolution timestamp and parent link. Earlier warmup blocks outside that collection retain the original indexer's finalized boundary attestations; later out-of-range blocks are rejected. The latest closing block and successor must both be covered, and a successor at the first covered height must authenticate the earlier closing hash through its parent link. This restores the original source's trust semantics: callback collection begins just before the first episode and never claimed to independently collect all 200 warmup hours. Missing in-range metadata still fails. It does not add a new qualification relaxation or manufacture earlier canonical block evidence.

Availability follows the original v2 model. A history read is rejected before the latest successor's indexed second upper bound plus declared finality and publication delays. `availableAtMs` is the maximum of that publication time and the check time plus declared history-read delay, and must fit within the original check cutoff. Actual block timestamps stay distinct from the conservative indexed-second upper bound. The current wall clock is never read.

Original acquisition timestamps remain unchanged inside the hashed artifact. They must be nonnegative, ordered and within the original maximum 30-second operation; they may come from an entirely different wall-clock epoch than the historical observations. Shifting those audit timestamps changes the original evidence digest but cannot change candle values or modeled availability.

Tests build synthetic original artifacts using the actual history reader with a fake fetch function. They cover corrupted wrappers, bodies, requests, cursors, assets, times, denomination, metadata and normalized projections, as well as size limits and volatile acquisition timestamps. No actual study or validation data is read.
