# Prospective native opening capture

`prepareAccumulationOpeningCapture` in `scripts/bots/accumulation-opening-capture.ts` is a two-phase read-only owner for the separately versioned available-finalized opening mark. It uses the existing exclusive capture store, original bootstrap planner and bounded injected transport. It does not modify sealed acquisition/reducer contracts or fetch close history, native swap quotes, payment estimates or model results.

Supply exact compact JSON plus LF and its independently registered SHA-256. The registration contains `kind: accumulation-opening-capture-registration-v1`, an exclusive `attemptName`, `episodeId`, `slotId`, aligned UTC `openingAtMs: H`, original `deadlineMs: H + 24 hours`, and independent runtime metadata/code/version/denomination pins. No replacement model or financial limit is accepted. The base directory must already exist at its canonical nonsymlink absolute path.

1. Prepare durably before H−20 seconds. Preparation that crosses this bound retains a failed seal.
2. Explicitly invoke `bootstrap()` once in `[H−20s,H−5s)`. Its first finalized-head discovery fixes the target permanently. The two discovery requests and original14 bootstrap requests, including their durable phase completion, must complete before H−5s. Later finalized headers can validate but never replace that first target.
3. Explicitly invoke `capture()` once in `[H−3s,H]`. It obtains only the seven original pool-state keys for the fixed target, with original request ID1000. The original response must arrive in `(H−5s,H]`; the native block must precedeH and be no more than60seconds old under the opening verifier. The owner additionally bounds original arrival by both the original preparation and capture entry/fetch-dispatch monotonic clocks plus the transport's original elapsed time. A wall rollback between phases cannot renew H or the bootstrap cutoff.

There is no implicit wait, retry, resampling, automatic restart or recovery. An early phase call rejects without dispatch; a missed due window is retained as a terminal failure. Concurrent/repeated phase calls cannot acquire a second target. The fixed endpoint is `https://ws.mof.sora.org/`; required injected fetch and original transport enforce its request allowlist, no redirect/fallback, byte limits and timeout. Bootstrap is capped at16 requests/6MiB; pool capture atone request/64KiB. The whole store is capped at32MiB/64records. The shared external abort stops only this owner's transport.

Exact original request/response bytes, clocks and failures are retained through the existing recorder. The raw opening evidence, independent trust projection, phase clocks, verification summary and final inventory seal are separate exclusive records. Storage/acknowledgment uncertainty leaves this owner unresolved and throws; it never resets its directory, emits a clean success or tries again. The caller must preserve those remnants for explicit recovery.

Verification and durable persistence may finish afterH. The opening cutoff applies to the original observed receipt, not a fabricated fsync timestamp. The returned `completedAtMs` is actual completion after sealing; `contemporaneousReadyClaimed` is always false. A later admission owner must assess its own current clocks and keep the original receipt unchanged.

`isAcquiredAccumulationOpeningCapture(result)` recognizes only this process's successfully acquired, verified and durably sealed result. A pure verifier result or JSON copy does not pass. The result exposes its readonly original registration, registered slot and verified mark. It does not claim this block was the final H-minus block, continuous risk coverage, a qualified strategy, actual funded wallet holdings, an executed trade or paid fee. Financial, qualification and model-evaluation flags remain false. Tests use invented metadata and receipts with a real temporary filesystem; no live collection is part of this module's validation.
