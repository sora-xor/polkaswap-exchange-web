# Finite catalog execution model

`readGoalTargetExecutionModel` accepts two distinct V3 execution-model schemas. The existing `source130-target131-readonly-counterfactual-v1` schema remains a single source130 model. The new `source128-129-130-target131-readonly-counterfactual-v1` schema requires the exact ordered source128, source129, source130 identities in `GOAL_CATALOG_TARGET_SOURCE_PROFILES`, catalog SHA256 `7e23e21b5133e191c48a7a6015ba542e200a412f8883e099bd2cb3a521c50210`, and the unchanged exact runtime131 target and compressed artifact pin. It requires `implementation.catalogCodecSha256` alongside the host, state codec and quote codec source pins. These are declared provenance, not decoder ownership or qualification authority.

`goalTargetSourceRuntimeProfiles(model)` returns the validated finite source set. `isGoalCatalogTargetExecutionModel(model)` narrows already parsed data. `goalQualificationPolicy(protocol, model)` returns `GOAL_QUALIFICATION_POLICY_CATALOG_V3` for the catalog model; omission retains the old source130 policy. Callers that hold a V3 plan must supply its model. Both policies keep the same budget, duration, target, drawdown, inventory sizing, cooldown, price impact, slippage, clock and fee stress rules. V1/V2 retain their existing runtime restrictions.

The V3 qualification plan must exactly match its model's one-source or three-source set, including order and all metadata/code identities. A numeric version range, duplicate, subset, target-as-source profile or changed catalog hash is rejected. The catalog-backed evidence producer must independently verify actual per-block code and metadata against the owned decoder catalog; the model parser does not authenticate RPC state.

For the catalog model only, each valuation event includes `runtimeProfileSha256`. The causal evaluator validates the actual context profile against the model, requires the quote's complete mark, block and source profile to equal that valuation, and refuses conflicting runtime identities for a repeated block hash. It emits the quote source digest, the separate target runtime digest and model digest on each fill. Qualification recomputation requires the valuation identity to belong to the exact source set, rejects conflicting repeated-block associations, and joins each fill's source digest and entire mark to its signal's valuation. Old V1/V2 and source130 V3 event shapes remain unchanged.

Qualification profile digests cover only `specVersion`, `transactionVersion`, `metadataSha256` and `codeHash`. The raw metadata catalog profile additionally includes `genesisHash`, so its `profileSha256` intentionally differs. Producers must compare the full authenticated catalog entry, then project the four qualification fields; they must never copy a raw catalog digest into an execution event. Candidate genesis remains independently bound by the plan/evidence source.

Both models retain the actual agreeing `query_info` and `query_fee_details` amounts, reject estimates above the explicit positive native-XOR cap, and charge the entire cap for hypothetical fills. The cap is at most the separate 1 XOR reserve and must be chosen before training; the parser chooses no fee amount. Live qualification still admits only the target131 profile and enforces the same cap. The original minimum-output fill model has no market feedback and is not a claim of historical dispatched execution or profitability.

Validation uses invented prices/receipts with the real signal evaluator, exact ledger and qualification boundary. It covers three-source transitions, partial fills and source/valuation/quote joins, wrong roles, profile/order/model/policy changes, fee cap accounting, release round-trip and unchanged older paths. No study registration, market acquisition or default GO activation is performed by this change.
