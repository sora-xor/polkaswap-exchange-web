# Prospective capture owner

`prepareAccumulationCapture` in `scripts/bots/accumulation-capture.ts` joins the original public hourly close, native bootstrap, fixed partial quotes, bounded fees and durable filesystem store. It collects one observation and invokes the existing evidence bridge. It has no model, strategy-selection, wallet, signing or transaction operation. A verified capture is not a qualifying strategy or profitable trade.

Prepare before a registered future window with an existing canonical `baseDirectory`, exact compact JSON plus newline `registrationBytes`, their independently expected SHA-256, and an explicitly injected `fetch`. The registration has the versioned kind, unique `attemptName`, `opensAtMs`, exclusive `closesAtMs`, `completedHourMs`, and independently established runtime metadata SHA-256, code hash, spec/transaction versions and denominator. The window lasts at most 60 seconds inside one completed hour. The target-selection rule is fixed in code: the first finalized head observed after the completed-close request. Registration bytes and the actual preparation record must be durably acknowledged before the window opens. A supplied digest establishes a byte binding; it does not authenticate how the operator established the original runtime pins.

The returned owner exposes `directory` and a single `collect()` attempt. The caller supplies the schedule; there is no background timer that starts collection, automatic retry, stale-lock deletion, recovery, or reopening. An early call rejects without consuming the attempt. A missed window is retained as a failed attempt, never resampled. A crash leaves the exclusive directory for inspection, not a successful terminal result. Multiple hours require separately prepared observations and complete external schedule accounting.

Collection performs these steps:

1. Retain one exact public indexer request and response for KUSD and XOR's last completed hour.
2. Retain two native discovery calls, then the bridge's original 14-call target, parent, finality, runtime and metadata transcript. The selected target is also the fixed finalized anchor. Reject changed registered runtime pins.
3. Request the original seven storage keys, decode actual asset precision and pool state, and verify the registered denominator.
4. Record all nine inputs from 1 through 9 KUSD. Each available quote determines its two bound fee calls. Nine bounded lanes avoid serial WAN round trips; each lane preserves quote → fee info → fee details order. There are at most 28 quote/context/fee requests, no retries, and a shared response budget. Null routes and failed replies remain in their original positions.
5. Construct the packet at the actual decision clock, persist its original receipts and separate source bindings, invoke the unchanged bridge, and seal the complete file inventory. Interrupted or invalid collection retains a failed terminal record when storage remains healthy. Storage uncertainty throws and preserves the incomplete directory.

The original five-second context and quote lifetime, 60-second block age, nine sizes, 0.5% minimum-output allowance and 1% impact cap are unchanged. A separate monotonic five-second bound starts conservatively before the original context dispatch, and the complete capture also has a monotonic window bound. Wall-clock changes cannot extend collection or renew old evidence. A slow capture remains unusable; persistence and fee responses never renew its timestamps. The bridge's verification describes the recorded decision time. Any later consumer must check original expiration again, including after durable writes and model computation.

Only `https://pi.soramitsu.io/graphql` and `https://ws.mof.sora.org/` receive these read-only requests. The source contract remains trust in those endpoints, not independent consensus or historical arrival evidence. The collector does not populate an old historical partition, fabricate missing state, open protected validation, perform causal execution replay, or establish complete episode coverage. Those requirements, prospective qualification, and personal wallet approval remain separate.
