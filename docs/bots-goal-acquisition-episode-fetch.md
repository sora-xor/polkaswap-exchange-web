# Acquisition episode fetch composition

`createGoalAcquisitionEpisodeFetch` in `scripts/bots/goal-acquisition-episode-fetch.ts` is a Node-only, opt-in adapter for an explicitly registered acquisition continuation. It combines the privately owned raw-response prefix from `goal-acquisition-replay` with the recorded history retries from `goal-acquisition-transport`. It grants no qualification, trading or wallet authority.

Supply a physical `fetch` controlled by the runner's aggregate request/spacing policy, the ordinary metadata-cache `marketFetch` whose pool delegation uses that same physical adapter, the episode evidence sink, and the evaluator's episode signal. Supply `preparation` only for the first continued training episode. Return only `{ fetch: adapter.fetch, marketFetch: adapter.marketFetch }` to the evaluator's dual-lane factory; retain `adapter.completion` separately for the continuation store.

Both original lanes must match their complete, ordered prefix before the exact failed history request can be acquired. A mismatch fails the episode and never enables live fallback. Every replay use and every physical history attempt receives a canonical-hash sink acknowledgement before response release. The acquired boundary body must finish before an owned completion is captured. This captured proof survives normal evaluator cleanup that aborts the episode signal, and `completion()` returns it after cleanup. A partial boundary, cancellation or transport failure does not produce proof. Later traffic switches explicitly to the supplied ordinary and metadata adapters after that proof exists.

The per-episode request limit is at most 10,000 and response limit at most 256 MiB. A continued episode begins with one request and the original failed response's exact bytes already charged. Each replayed outer request and first new attempt is then charged once; extra retry starts each consume another request. Replayed successes, ordinary RPC and metadata responses charge their observed body chunks. The retry adapter charges all observed error and successful bytes, so its returned body is not charged again. An over-limit observed chunk remains in the audit count and is not released. Metadata cache hits do not pretend to be physical starts; aggregate physical starts remain the runner's responsibility, including the original preparation's `originalPhysicalStarts`.

One history operation is identified by the original reader's `RequestInit.signal`, which it shares across all pages. Its absolute deadline begins at its first request, including replayed pages, and never renews on retry or cursor changes. It permits at most eight pages and 8 MiB across replayed page bodies, the original failure at its exact boundary, and all new retry bodies. Each new history response also has the reader's 2 MiB limit. Only the original failed request receives a carried attempt, binding the exact URL, headers and body; its two remaining starts cannot reset. New cursors retain the declared three-attempt policy. Each operation uses the configured timeout (normally 20 seconds, at most 30 seconds).

Requests are serialized across both lanes and their response bodies. An unread or cancelled body cannot be skipped to start another request. The adapter permits only the existing indexer history endpoint and read-only archive RPC methods. `dispose()` revokes further transport use. Tests use synthetic retained records, fake clocks and fake fetch functions; they perform no network or market acquisition.
