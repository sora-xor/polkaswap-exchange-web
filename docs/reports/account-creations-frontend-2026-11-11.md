# New Accounts creation counter — frontend release

The mainnet Stats card now requests the independently covered `NetworkSnapshot.accountCreations` field through `accounts: accountCreations`. This measures finalized `System.NewAccount` events, including accounts recreated after removal. It no longer depends on the recovered first-participation projection or personal Points ownership evidence. Missing creation coverage remains unavailable; a complete observed zero remains zero.

The calendar and BLOCK operations are named `NetworkChartCreationFlows` and `NetworkChartCreationGapBlocks`. The API's legacy `accounts` field remains unchanged. Non-mainnet deployments, fees and volume use the existing query documents. If an alternate mainnet schema rejects the new query before returning calendar data, the client makes one bounded read through its legacy schema for the other three counters and explicitly clears New Accounts. It cannot substitute a legacy participation count for a creation count. Both attempts use the same captured endpoint.
