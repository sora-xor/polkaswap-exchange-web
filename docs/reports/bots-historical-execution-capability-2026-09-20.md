# Historical execution evidence capability — 20 September 2026

The current simple-flow replay places completed-hour signals at the next hourly close. Live execution obtains a fresh quote on the next eligible scheduler/finalized tick. The difference can create a historical opening loss before any modeled fill. Replacing next-close marks with same-close prices would not establish causal execution evidence.

## Data still needed before changing production replay

Hourly indexer rows contain boundary reserves and successor identity, but not successor quotes or fees. Periodic pool charts do not supply a complete, denomination-bound execution record. A separate record must bind a known completed signal, a predetermined later execution state, amount-specific quote, historical runtime/metadata, route and source policy, precision, denomination, minimum output and fee estimate. Missing observations must remain failures. Archive state timestamps do not establish when that state was historically received by a browser or that a transaction was included.

The deployed frontend currently discards the validated close/successor provenance when converting pool rows to candles. The new `parseIndexedPoolHistoryWithEvidence` API preserves it separately, but the fetch layer and production replay still use the compatibility wrapper. Portfolio and idle valuation also require same-state marks; the new pool codec supplies exact reserve ratios at a bound state, while live valuation currently uses route-derived `amountWithoutImpact`. An amount-specific quote is not a spot mark. Finally, this archive reader uses direct DEX 0 XYK quotes while live route selection currently permits other routes. A new protocol must bind matching route and valuation behavior rather than assume the two are interchangeable.

Any finer historical experiment requires a separately versioned protocol fixed before reading its outcomes. It must preserve 10 KUSD maximum starting capital, partial orders, the 1 XOR reserve, 5% loss bound, 1% impact cap, 0.5% slippage, fixed 24-hour episodes, candidate count and untouched validation. It must distinguish archived quote scenarios from actual fills, preserve gaps and rejected orders, and evaluate current execution costs before a live review. A successful archive capability check does not bypass GO qualification.

The existing day-001 collection remains unchanged. Its fixed 5 KUSD notional and 3% development impact policy cannot be presented as 1% GO validation. No new long-running dataset was started by this capability check.

Evidence is retained under `output/go-history/execution-archive-capability-20260920/`. The full trading objective remains incomplete: no strategy qualified, no transaction was submitted, and no successful trading video exists.
