## What executed

The new host is an additive copy of the strict declared-storage host, with genuine Sr25519 verification and standard compressed ECDSA public-key recovery using installed cryptographic libraries. Unknown storage, prefix scans and host functions still fail. The process ran under the existing macOS network-denial profile; its probe returned `EPERM`. The signatures use a public test seed of `0x42` repeated 32 times. Sr25519 signing may produce different signature bytes on another invocation; each exact returned signature is retained.

The pool, payer, balances and fee multiplier are the earlier artificial fixture: 1,000 XOR / 10,000 KUSD pool, 3 XOR / 10 KUSD payer, native multiplier 1. Inputs are **5 KUSD** or **1 XOR**, not thousands of tokens. Every case starts from fresh state and memory.

Twelve actual `BlockBuilder_apply_extrinsic` calls cover:

- Five successful swaps with real Sr25519 or ECDSA signatures, both directions, all four compact nonce encoding widths (63, 64, 16,384 and 1,073,741,824), and a 215-byte ECDSA envelope at nonce 4,294,967,294.
- Mortal64 birth block 191, phase 63 and execution block 192, including the phase crossing the next 64-block boundary.
- An included dispatch failure with an explicitly impossible `u128::MAX` minimum: no output or pool changes, with the actual native fee and nonce increment retained.
- Corrupt signatures in both families, a stale nonce, a payload signed for runtime 130, a different checkpoint, and execution at the signed era's death block 255. These produce no trade, fee, balance or nonce effect. The stale-nonce case has one block-local `System.ExtrinsicData` write before rejection; it is not an included transaction. The receipt and assertions preserve this distinction.

The six included cases each execute both native fee methods. Their estimates agree and cover the settled fees. Synthetic actual fees increase from `721000000000000` to `721500000000000` XOR codec units with the encoded length. These are **synthetic fees**, not a replacement for the separately retained production fee observation or a future fee ceiling.

## Unchanged browser code actually checked

Same-phase/different-checkpoint signatures fail; the 130 payload cannot be captured as 131. A cryptographically valid signature with stale nonce, wrong chain checkpoint or expired lifetime remains a signed fact with `checkpointCanonicality: not-yet-checked`; it does not become an inclusion receipt.

The fee codec inspects the successful call/envelope bytes and confirms the 215-byte bound. Its minimum-output reference is explicitly invented structural input, not liquidity evidence. The impossible `u128::MAX` failed-dispatch vector cannot be generated by the supported slippage rule and is therefore used only for actual failed-dispatch/receipt handling; it does not claim successful fee-codec admission.

`goal-receipt.ts` consumes the exact actual-WASM `Vec<EventRecord>` bytes through the 131 registry. It identifies the correct output/native fee for successes and fee-only failures, and rejects absent inclusion effects, wrong-direction orders, duplicate fee events and missing fee events. The RPC-shaped finalized block wrapper is a local fake: this tests the receipt parser and its exact extrinsic/event joins, **not real chain finality**. Returned test receipts never enter goal storage or authorize a signer.

Nine focused unit tests pass. ESLint has zero errors. Scoped TypeScript has zero errors in the new files and the five already known liquidity-proxy errors. The standalone verifier is bundled with the installed esbuild, preserving source and bundle-input hashes; the one explicit ORML `utils/index.js` alias resolves a package ESM directory-import issue.
